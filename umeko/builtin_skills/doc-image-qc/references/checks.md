# 图片检查项清单（doc-image-qc 附属数据）

> 主 Agent 在阶段 2 派发每图质检任务时，从本清单选取适用检查项，
> 逐项写入子 Agent 任务描述；子 Agent 对每项给出结论。

## 通用检查项（所有图片）

| 编号 | 检查项 | 说明 |
|---|---|---|
| C1 | 图文一致性 | 图片内容与文中临近描述是否一致 |
| C2 | 图片质量 | 清晰度、文字可读性、构图完整性 |
| C3 | 敏感信息 | 公网 IP、版本信息、所有 IP、SNO/ESN、设备名称（如 DDM 左上角）、年月日、硬件编码、二维码 |
| C4 | 图片规格 | 原文件字节数、宽×高和总像素是否过大；报告脚本实测，不以模型缩小后的图片代替原图 |

C2 同时检查低清晰度：关键文字/数值、细线与图标能否辨认，有无模糊、压缩块、锯齿或放大失真，记录具体位置及对检查的影响。
不能仅因像素小或 DPI 低就判定低清；图标和完整页面截图用途不同。若视觉工具已缩小图片，区分模型输入丢失的细节与原图缺陷，无法核实原图时注明限制，不猜测读不清的内容。

C4 默认建议阈值为 5 MiB、最长边 4096 像素、总像素 1600 万；任一超出给 WARN，列出实测值和所用阈值，不把建议当作行业强制标准。
用户提供规格时使用其要求；缺少可读取的原文件或尺寸无法测量时标明未验证。文件体积、尺寸与清晰度分别判断，不能用“文件大”代替“清晰”。

## 原理图类

| 编号 | 检查项 | 说明 |
|---|---|---|
| S1 | 原理图-描述一致性 | 原理图与原理描述逐点核对 |
| S2 | 流程正确性 | 流程步骤与操作步骤描述一致 |
| S3 | 分支完备 | 判断节点的分支标注完整、指向正确 |

## 组网图类

| 编号 | 检查项 | 说明 | 备注 |
|---|---|---|---|
| N1 | 组网图正确性 | 拓扑、连线、设备角色正确 | 风险点，受限模型能力，建议复测 |
| N2 | 组网图-描述一致性 | 与组网描述文字互相印证 | 同上 |

## 界面截图类

| 编号 | 检查项 | 说明 | 备注 |
|---|---|---|---|
| U1 | 界面截图正确性 | 截图与描述的实际操作界面一致，信息项不多不少 | |
| U2 | 界面-实际一致性 | 界面内容与真实产品界面核对 | 模型能力待验证 |
| U3 | 截图-步骤一致性 | 截图处于操作步骤描述的正确阶段；步骤点名的菜单/按钮/页签在截图中存在且名称逐字一致 | |
| U4 | 敏感信息（增强） | 在 C3 基础上逐项扫描截图内可见文本 | |
| U5 | 界面术语一致性 | 截图中菜单名、字段名、按钮文案、页签、单位符号（如 ℃）、专有名词与正文及实际界面用语逐字一致；术语不符（如"资讯"误作"信息"）、生造词、单位符号不规范均计入 | 术语与正文不符 = **FAIL**，不得降为 WARN |
| U6 | 输入输出与描述一致性 | 核对输入来源、字段、数据类型、方向、范围/单位，触发动作与输出结果、状态、目标位置是否与正文/参数解释一致；多图时核对步骤之间的数据传递 | 截图不能证明后台真实执行结果；缺输入输出说明时 NA，不凭静态控件猜业务行为 |
| U7 | 默认值与参数说明 | 核对截图默认值、选项、开关及单位是否与参数解释一致，是否越界、互相冲突或包含危险默认值 | 区分默认值、当前已填值、占位符与示例；无法确定是否初始状态时 NA |
| U8 | 高危操作提示 | 对删除、清空、覆盖、恢复出厂、停机等操作，核对可见提示与正文所述风险、影响范围、对象及确认步骤是否一致，有无误导或关键信息遗漏 | 单张普通页面未出现确认框，不代表后续没有确认；只按已提供的操作阶段与风险依据判断 |
| U9 | 必选参数星号标识 | 由参数解释或 schema 确定必选、条件必选与可选字段，逐字段核对必选输入是否有可见的 * 标识，以及可选字段是否被误标 | 不凭字段名推定必选；只读/派生展示项不要求星号，条件必选须先核实条件；截图裁切、文字不可读或缺少解释时 NA |

U6-U9 的依据应写进各自 note：参数名/控件位置、截图可见内容、说明原文及位置、两者差异和建议。
例如参数表明确“服务地址：必选”，完整字段区域可见且没有星号，可记 U9 FAIL；没有参数解释时不能按“看起来重要”判成必选。
截图明确处于初始状态且默认值与说明冲突，可记 U7 FAIL；已填入的自定义值或灰色占位文字不能直接当作错误默认值。

## 用法

- 主 Agent 阶段 1 建清单时，根据图片上下文给每张图标注适用检查项分组
  （通用 / 原理图 / 组网图 / 界面截图，可多选）。
- 阶段 2 子 Agent 任务描述格式：
  「检查项：C1 图文一致（…）；N1 组网正确性（…）… 每项给出 PASS/WARN/FAIL
  与一句话依据」。
- 缺少正文或真实产品参照时，相应检查项记 `NA`（未检查）并说明原因，不把猜测写成事实。
- **判定级别纪律**：有证据的事实性不一致（含术语与正文不符、步骤顺序错误、信息项多/缺）
  一律 FAIL；WARN 仅用于"确认存在但影响轻微"的问题（如措辞省略但语义完整、
  风格差异）。无法确认的问题标明需要人工复核，不在缺少证据时判定 FAIL。
- 结论按检查项维度写入 qc-report.json（见主文档阶段 2 的 JSON 格式）。
