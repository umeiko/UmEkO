# 平台介绍与服务边界

## 平台做什么

UMEKO 在一个共享运行时上提供多个可发布的智能体。模型供应商、工具、技能文件、用户会话、机器任务和管理员配置分开管理；不同智能体可以共用模型连接和排队机制，同时各自配置介绍、工作指引、默认主模型/视觉模型与技能范围。

网页工作台用于人机协作，CLI 用于本地终端使用，REST/MCP/A2A 面向外部程序或 Agent。此管理 Skill 通过管理 API 配置服务器，业务任务由发布后的 Agent 入口执行。

## 两个地址不能混用

| 对象 | 默认入口 | 身份与作用 |
| --- | --- | --- |
| 管理面与管理 API | 9000；独立 `UMEKO_ADMIN_BASE_PATH` | 管理员 Cookie；配置、授权、查看历史 |
| 用户工作台与机器服务 | 8000；`UMEKO_BASE_PATH` | 网页用户 Cookie 或机器服务凭据；实际执行任务 |
| Provider `base_url` | 上游模型平台提供的地址 | 只有服务器连接模型时使用，不是 UMEKO 管理地址 |

生产中的域名、端口、前缀以用户提供的入口为准。复制提示词中的管理基址已经包含管理前缀，调用脚本的路径保持 `/admin/...`。`UMEKO_PUBLIC_URL` 是机器和用户服务的外部完整地址，它的路径需匹配 `UMEKO_BASE_PATH`，不是管理地址。

管理 Skill 的说明和 ZIP 公开下载；所有 `/admin/v1/` 数据与操作仍需要管理员身份。机器服务设置为免鉴权不会开放管理 API。

## 智能体与技能

一个智能体通过 `/agent/<slug>` 独立发布以下入口：

```text
/.well-known/agent-card.json
/a2a
/mcp
/v1/tasks
/oauth/token
```

这些后缀必须接在用户服务基址的 `/agent/<slug>` 后面，不存在顶级 `/a2a` 或 `/mcp` 入口。发布后以管理 API 返回的 `endpoints` 为依据。

Agent Card 是公开的能力简介；其中 Skills 对应该智能体选择的技能简介，不能公开完整工作指引、脚本或 Provider 密钥。MCP 的 `tools/list` 是协议请求，通过官方 MCP 客户端调用，不是 HTTP `/mcp/tools/list`。

技能库是管理员维护的源文件，默认下发配置是数据库中的入口记录，用户 Session 得到的是独立副本。保存源文件、导入下发、批准受保护代码分别是不同动作。`.py` 与 `config.json` 执行前按白名单和摘要核对，更新说明见 [配置指引](configuration.md) 和 [接口行为](api.md)。

## 会话、机器任务与临时工作台

- 普通网页用户有自己的持久化会话和文件。
- 每个机器任务保存执行状态、上下文、工具过程与产物元数据；调用方保留提交时返回的 task_id。
- MCP `submit_task` 和 REST 提交快速返回；A2A 使用 `returnImmediately=true` 可避免长连接等待。提交成功只表示已接收，不能当作业务完成。
- 返回的 `workspace_url`（A2A 为 `metadata.workspaceUrl`）指向 `/TMP/<临时令牌>`；及时作为可点击链接交给用户，可以观察进度、补充材料并继续处理。同事无法访问时应检查其网络，而不是改用环回地址。
- 临时节点继续对话也不会变成永久节点。纯机器空闲和人工接续后的空闲期限不同，具体以服务返回的有效期和工作台提示为准。保留需要的结果，到期后重新提交；不要反复访问旧链接尝试恢复。

模型并发按注册表模型 ID 共享，`0` 表示不限制。流式请求结束后才释放额度；排队不代表失败。平台是单个运行进程的共享运行时，不能仅增加副本数就假定会话和队列已经具备跨节点共享能力。

## 管理者能配置的范围

用户与角色、模型/工具权限、Provider/模型、每模型并发、默认模型、工具回合、智能体、机器鉴权方式与服务凭据、技能源文件/下发/可信代码、任务取消、会话驱逐或清理和监控读取均有管理 API。浏览器主题/语言是本地偏好；端口、TLS、路径前缀、数据目录和反向代理是部署配置，修改后可能需要重启，由服务器操作者处理。

包中不含目标服务器的账号、密钥、用户文件或数据库。离线 API 文档是版本快照，操作前读取目标服务的在线规范。
