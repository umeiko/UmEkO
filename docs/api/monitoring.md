# 管理员资源监控

登录独立管理端，在顶部选择“资源监控”。页面每 5 秒读取一次数据，保留最近约 10 分钟趋势；切换到其他页面、隐藏浏览器标签或退出后停止轮询。

| 指标 | 测量范围 |
| --- | --- |
| 服务器 CPU | UMEKO 所在机器的总体 CPU 使用率与逻辑核心数 |
| 服务器内存 | 整台机器使用量、总量、使用率 |
| 数据所在磁盘 | 数据目录所在卷的已用、可用与总容量，不是 UMEKO 目录单独占用 |
| UMEKO 进程 | 主服务进程的 RSS 内存、CPU、线程数；进程 CPU 100% 约等于占满一个核心，可能超过 100% |
| 服务状态 | 网页会话、机器工作区、内存会话、Run 状态、数据库与 WAL 文件字节数 |
| 模型队列 | 每模型并发上限、正在调用、等待调用 |
| 机器任务 | 状态数量、任务 Worker / 队列 / 调用者容量、保留时间，最近 100 个任务及停止按钮 |

GPU 不在当前监控范围。远端模型服务器的 GPU、显存和模型平台流量需在 LiteLLM 或模型提供方监控中查看。容器部署时 psutil 的主机 / 容器可见范围与平台有关，不应把这些读数直接当作 cgroup 配额使用率。

“服务接入”负责创建、停用和更换机器凭据，并展示协议入口。凭据只显示一次；列表只含名称、权限、状态与到期时间。管理员停止任务使用共享取消机制，不会强制终止整个服务。

API：

| 方法 | 管理端口路径 | 返回 |
| --- | --- | --- |
| GET | `/admin/v1/resources` | `current`、`history`、`interval_seconds` |
| GET | `/admin/v1/tasks` | 最近 100 个任务的归属、来源、状态与时间，不包含输入正文和模型密钥 |
| POST | `/admin/v1/tasks/{task_id}/cancel` | 请求取消后的任务 |
| GET / POST | `/admin/v1/service-accounts` | 账号列表 / 创建账号并返回一次性凭据 |
| PATCH | `/admin/v1/service-accounts/{account_id}` | 启用、停用或更换凭据 |

这些接口只接受管理员 Cookie。普通用户服务端口不暴露管理 API。采样在后台执行，HTTP 返回已采集的数据；重启后趋势重新开始，不作为长期监控或审计存储。
