# 受控技能与执行信任

受控技能允许管理员下发经过审查的 Python 程序，让 Agent 使用这些程序处理文件；用户和模型可以调整会话中的说明、样式和普通资料，但不能把上传或改写的代码变成可执行技能。网页、REST、MCP 和 A2A 使用同一套服务端门禁。

部署操作见[技能部署、升级与 MD5 排查](../deployment.md#skill-security-upgrade)。本页说明当前已经实现的机制，不代表操作系统沙箱或脚本安全审计。

## 技能库、会话副本和批准记录 {#trust-layers}

| 对象 | 位置 | 作用 |
| --- | --- | --- |
| 随版本发布的内置模板 | 应用包内的 `umeko/builtin_skills/` | 安装来源；升级时只替换可识别的原版，保留管理员自定义和删除 |
| 管理员技能库 | `UMEKO_SKILL_DIR`；未指定时使用应用的默认 `skills/` | 管理员审查和维护的源文件；保存不等于批准，应使用固定的持久化目录 |
| 库文件版本白名单 | 数据库 `skill_file_approvals` | 管理员显式批准的包内路径、MD5、SHA-256、操作人及时间 |
| 撤销记录 | 数据库 `skill_file_revocations` | 文件最近一次移出可信区的授权序号；拦截此前已经下发的版本 |
| 会话技能副本 | `UMEKO_DATA_ROOT/users/<user_id>/sessions/<session_id>/client/skills/<pack>/` | 此会话实际读取的指引、脚本、辅助模块和配置 |
| 私有批准记录 | `UMEKO_DATA_ROOT/skill_trust/<session_id>/<pack>.json` | 记录包名、允许执行的 Python 路径，以及受保护文件的 MD5、SHA-256 |

管理员在“技能库 → 选择 Python 或 config.json → 安全门禁”点击“加入可信白名单”，服务从**已保存的管理员库文件**重算 MD5 与 SHA-256，持久化对这个具体版本的批准。保存、上传、应用升级或重启都不会自动批准新版本；未批准文件显示“当前版本未加入白名单”，批准后变化显示“文件已变化，需重新确认”。

创建会话时，服务复制技能包，但私有批准记录只使用数据库中管理员已确认的摘要，不能拿刚复制的文件自行生成授权。未批准文件不能执行；源文件变了而未重新批准时，即使已复制到新会话，也会因摘要不匹配而拒绝。记录不由用户副本生成，不接受用户提交，也不会写入用户可访问的技能目录。入口、辅助 Python 模块和 `config.json` 均需确认。

数据库中的技能启用状态和 Agent 技能披露决定下发范围；仅在磁盘放一个 Python 文件，不等于已经下发或获得执行权限。`mounted` 控制按需加载目录，不是安全授权开关，见[技能加载](index.md#skill-loading)。

## 哪些文件可以修改

| 内容或操作 | 普通用户、会话模型 | 管理员技能库维护 |
| --- | --- | --- |
| `SKILL.md`、`references/style.md` 等普通资料 | 完整工作台的会话副本可编辑；临时工作台的网页技能区只读 | 可维护可信源 |
| `.py` 和 `config.json` | 可以读取，不能新建、修改、删除、剪切或改名 | 可以审查后维护；修改后需再次批准当前版本 |
| Python 字节码、原生扩展、`.pth` 等导入相关文件 | 同样受保护；旧 `__pycache__` 不进入执行副本 | 管理员负责审查运行依赖 |
| 上传、复制、移动、目录整体操作、下载落盘、7-Zip 解压 | 不能间接产生或改变技能目录中的受保护文件 | 不通过普通用户文件操作更新可信代码 |
| 工作区里的 Python 产物 | 可以作为文件保存，但不会因此获得技能执行权 | 需审查并放入技能库，通过正常下发使用 |

门禁在后端执行，网页“只读”提示只是交互反馈。改文件后缀、在压缩包中夹带文件或修改网页属性，都不能获得执行授权。`config.json` 中的二进制位置等配置属于可信代码的运行配置，不能通过会话编辑它来切换外部程序。

## 一次脚本调用检查什么 {#execution-checks}

1. 检查 Agent 的技能范围和工具权限，以及包名、包内脚本位置；拒绝路径穿越、链接及目录绕行。
2. 检查私有记录中的包名和脚本白名单，并查询管理员撤销记录。文件被移出可信区后，此前下发的入口、辅助模块或配置会阻止整个包继续执行。脚本存在不代表允许执行。
3. 检查**整个技能包的受保护文件集合**，逐个比较 MD5，再比较 SHA-256。辅助 `.py` 模块和 `config.json` 也参与；多出、缺失或改变文件都会拒绝执行。因此错误可能指向另一个辅助模块，而非本次入口脚本。
4. 将刚刚校验过的代码、配置字节及当前普通资料复制到短期私有执行目录，排除旧字节码，隔离外部 Python 路径注入，再启动脚本。执行不重新打开用户目录中的原脚本，避免检查后替换。
5. 执行结束清理短期副本；会话删除或临时节点回收时清理该会话的批准记录。

信任检查失败返回 `SCRIPT_TRUST_REJECTED`；MD5 失败会给出第一个不匹配的包内路径，此时脚本尚未执行。摘要比较的是**原始字节**，不是解析后的 Python 逻辑或 JSON 对象：LF/CRLF、UTF-8 BOM、空格、JSON 缩进的变化也会改变摘要。

MD5 和 SHA-256 只证明字节与批准版本一致。它们不证明程序无漏洞、外部二进制安全、Python 依赖已安装或模型服务可用。管理员批准的脚本仍具有服务账号的系统权限。

## 升级与会话生命周期 {#upgrade-behavior}

会话副本和批准记录共同代表已下发版本。**更新管理员库不会自动覆盖旧会话，也不会自动撤销旧版本。**

| 场景 | 当前行为 | 维护者应做什么 |
| --- | --- | --- |
| 新建会话 | 从当前管理员库复制文件，采用已批准的摘要生成私有记录 | 先确认整包代码与配置的当前版本已批准，再新建会话验证真实入口 |
| 已有记录的旧会话恢复 | 保留原副本和原记录；即使库已更新，二者匹配仍可执行旧版 | 若需新版，真正新建会话；确认旧依赖仍兼容 |
| 首次启用库文件版本白名单 | 现有库文件不自动批准；旧会话已有记录保留，缺少记录时只采用显式批准摘要 | 管理页逐文件确认当前库版本，再新建会话；不修复旧会话 |
| 旧会话脚本或配置被升级脚本覆盖 | 原批准记录保留，改后的字节不匹配会拒绝 | 恢复配套备份，或从审查后的库新建会话 |
| 清空聊天、刷新页面、重启服务 | 不刷新已经下发的技能版本和摘要 | 不能当作升级技能的操作 |
| 复制已有会话 | 复制原文件和已有批准记录 | 不能代替“新建会话”取得新版或修复不匹配 |
| 恢复备份、跨平台迁移 | 保留字节和匹配记录才可继续信任旧会话 | 数据、会话文件和记录成套恢复；不要自动转换换行 |

如果安全问题要求撤销旧程序，可以在“可信代码管理”选择相关文件并“移出可信区”。该操作拦截已下发版本的后续调用，但不强行终止已启动的脚本。需要立即停止正在执行的任务时，另行取消任务或停止服务。升级本身不会自动覆盖旧副本、重新批准或撤销授权。

MCP/A2A 新任务在执行时创建新的服务会话；临时工作台继续对话仍使用原会话。排查时核对任务详情中的实际 `session_id`，不要只凭“又调用了一次工具”判断已经换新；复用幂等键也可能返回原任务。

CLI 直接调用使用管理员控制的技能库，在执行前从该库临时生成信任记录并校验私有副本，不使用服务器的持久会话记录。随意指定一个会话目录不会被当作可信库。

## 管理员文件安全门禁 {#administrator-approval}

在管理端“技能库”选择 `scripts/` 下的 `.py` 或 `config.json`，保存后点击工具栏“安全门禁”。弹窗显示当前版本的可信状态、当前双摘要以及最近批准版本的双摘要、确认人和时间。“加入可信白名单”只批准这个文件的当前内容，已经匹配时按钮显示“已在可信白名单”。

请求只携带页面读取到的 SHA-256 作为版本检查；服务从管理员库读取文件并计算批准摘要，不接受客户端传入内容、操作人或其他文件的批准值。源文件在查看后变化返回 `409`，需要刷新再操作。批准和审计事件在数据库同一事务中提交；事件保存在 `skill_file_approval_events`，与最新版本表一起随数据库备份。旧版会话维护事件不自动转成库文件批准。

操作只影响后续新会话下发与管理端脚本测试，不重新下发、覆盖或重新批准旧会话。入口、辅助模块及配置必须全部匹配才能执行，不扩大 Agent 的技能披露范围。批准过程不执行脚本；服务重启后保留批准状态，文件字节变化则需再次确认。具体步骤见[部署指南](../deployment.md#skill-admin-reapproval)。

### 整库可信代码管理 {#library-trust-management}

管理端“技能库”标题旁的“可信代码管理”汇总库内 Python 文件、`config.json` 和仍保留的授权记录。可以按技能、文件类型、信任状态筛选，按技能名或包内路径搜索；列表分页加载，展开文件查看当前摘要、批准摘要及操作人时间。文件缺失、路径异常也会显示，已保存的授权仍可移出，不能把异常路径加入可信区。

支持逐项选择、跨页保留多选、“全选当前页”及“选择全部筛选结果”。改变筛选会清空选择，避免批量操作隐藏的旧选择。全选筛选结果由服务端一次返回版本快照，执行时分为每批最多 200 个文件；后端逐文件核对版本，报告成功与失败。某个文件在选择后改变不会被静默批准，其他文件的成功操作保留。失败详情显示相应文件和原因。

“移出可信区”删除当前批准，并在同一数据库事务中记录撤销及审计。后续脚本调用检查该文件最近的撤销序号，**此前下发的所有版本均被阻止**，包含没有授权序号的早期会话记录。不会遍历、覆盖或重签会话文件，不会停止已经启动的脚本。

重新批准后，新会话取得新的授权序号；此前被撤销的旧会话不会自动恢复，必须新建会话使用重新确认的版本。仅撤销某个辅助模块或配置也足以阻止整包执行。撤销状态和审计随数据库备份、重启保留。CLI 本机操作者直接执行库文件不连接服务器数据库，故不受服务器撤销记录控制。
