# 常见问题与注意事项

## 提交请求被拒绝

| 反馈 | 原因与下一步 |
| --- | --- |
| 400 / MCP isError / A2A InvalidParams | 看 code、field 和 file_transport，修正结构后再提交 |
| FILE_CONTENT_IN_TEXT | 文件 base64、data URL 或附件 JSON 放错进正文；改用附件字段 |
| PROMPT_TOO_LARGE / 422 | 文本或请求 Schema 不符合限制；错误不会回显整段文件字节 |
| 401 / 403 | 检查服务凭据、scope、当前 Agent 与账号有效期 |
| 404 | 检查完整用户前缀、Agent 路径、任务归属与记录是否到期 |
| 409 | 同一幂等键对应的输入不同，或当前会话已有活跃 Run |
| 413 | 整条请求或上传体积超过限制 |
| 429 | 队列/调用者额度已满，按 Retry-After 稍后重试 |

门禁返回 `retryable=false`、`task_created=false` 时，没有 Task 和工作台节点。不要原样、拆段或换文本字段反复提交编码，也不要轮询不存在的 ID。

## 正文有下载 URL 会被拒绝吗

普通 HTTP/HTTPS 文件链接允许提交，长签名参数也不会被当作正文文件编码。提交阶段不验证链接能否下载。

下载、解压、读取或图像处理失败后，是否还有可行修正、关键材料是否缺失、能否继续其他部分由 Agent 判断。没有“一次工具错误就硬终止整项任务”的规则。确认无法继续时应及时提交情况说明、提供补齐步骤和工作台接续指引。

内网访问范围与证书信任仍由管理员配置。模型服务和文件下载使用不同的 HTTPS 配置；请管理员分别检查，不能要求模型自行关闭 TLS 校验或绕过目录权限。

## 提问成功，但一直没有回答

先看 queued / running，再检查任务 Worker 和每模型队列。MCP 用短提交、轮询结果；A2A 长任务用流式或 returnImmediately。代理需要转发完整子路径，SSE 关闭缓冲，并设置合适的读超时。首页可访问不代表协议、文件和登录都可用。

## 图片没有后缀或太大

图像工具按文件内容识别常见栅格图片，而不是只看扩展名。大图会在模型输入前等比缩小，原附件保留。默认最长边不超过 2560 像素、总像素不超过 400 万，GIF/TIFF/动画图只看首帧或首页并提示范围。缩放后看不清的细节应补充局部图，不能据此断言已经检查全部原始细节。

源图仍有安全解码上限；工具返回的损坏、超限或不支持格式信息需要由 Agent 结合任务说明处理。

## 哪些地址容易混淆

- UMEKO 用户服务基址：工作台、REST、MCP、A2A 共同使用的外部用户入口。
- UMEKO 管理基址：独立管理端口/前缀，供管理员登录和管理 API 使用。
- Provider base_url：上游模型接口，不能作为本平台机器入口。
- Agent 基址：用户服务基址再加 `/agent/<slug>`。
- 临时工作台：服务返回的用户基址下 `/TMP/<随机标识>`，不是 Agent 路径下的子接口。

## 提交故障信息时

提供发生时间、协议、Task ID、状态、错误码、预期结果和管理员查看到的相关工具反馈。不要附上模型 Key、服务 Token、真实下载签名或完整临时工作台能力链接。管理员通过任务 ID 查询原始记录即可。
